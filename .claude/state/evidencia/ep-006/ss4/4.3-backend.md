# EP-006 · ss4 · tarea 4.3 — revertir la última importación (backend)

- `antesDeRevertir`: importaciones aplicadas después (se comparan en SQL; en JS se perdían microsegundos y el lote se contaba a sí mismo) y perfiles cambiados después (`version` ≠ `version_aplicada`).
- `confirmarReversion` (panel): solo el último aplicado (`no_es_la_ultima` con las posteriores), `incluir` solo entre los cambiados (`incluir_invalido`), idempotente, encola `revertir_importacion`.
- `revertirLote` (worker, contrato I-2): candado, lote `FOR UPDATE`, restaura `estado_previo` (campos, hijas, experiencias vigentes; nada se borra), archiva los creados, deja los cambiados no incluidos, una subida de versión si el cliente ve algo distinto, auditoría `origen = reversion` con fila del lote. Si una regla de la BD lo impide → `no_se_pudo_restaurar` con el código. Fallo o retoma → el lote sigue aplicado con `motivo_reversion` y se puede reconfirmar.
- Panel: `GET/POST …/lotes/{id}/revertir`, `GET …/lotes` (historial; también la observadora).
- Pruebas: infra 3 ✓ (diff = 0 sobre todo lo que el editor ve del perfil, incluidas experiencias, sectores, motivo de pausa), worker 6 ✓, HTTP 4 ✓; suite completa 850 ✓ / 3 omitidos preexistentes.
- Mutación: sin restaurar hijas, ignorar cambiados, worker sin comprobar «última», no archivar creados → 4/4 MUERTOS.
